# **Monthly Progress Report — January 2026**

*Hadi Al Shmaissani · Project 3 · Supervisor: Prof. Naseem Daher*

**Abstract — **This report covers the first two weeks of the second term (January 20 – 31, 2026), continuing from the Milestone-1 progress report submitted in mid-January. The work this month focuses on translating Prof. Daher's January feedback into a concrete second-term roadmap and standing up the first version of the PyTorch DynamicWeightAgent that will replace the discrete Q-learner from the midterm. The headline feedback was that the Q-learner from the midterm is essentially memorizing rather than learning, since the supposedly impressive accuracy curve is computed against ground-truth labels generated by the same closed-form AI equation that produces the score. The new agent re-poses the task: instead of mapping AI scores to behavioral categories, it predicts the four AI weights themselves conditioned on environmental context. By the end of the month the agent's training loop runs end-to-end on cached telemetry with monotonically decreasing loss and held-out predicted weights within 0.01 L1 of the regime-appropriate hand-picked targets.

## **1. Introduction**

The Milestone-1 progress report documented the project's transition from the static rule-based pipeline to a dynamic Q-learning agent on the gymnasium highway-v0 environment, together with the closed-form Aggressiveness Index (AI) formulation across highway, urban, and friction-aware regimes. The report also enumerated four directions for the second term: (1) a properly trainable PyTorch-based DynamicWeightAgent that replaces the discrete Q-table; (2) a gating mechanism that lets the same agent shift smoothly between regimes instead of hard-switching; (3) a transition from highway-env to SUMO for population-scale simulation, with a CARLA prototype as a stretch goal; (4) the encapsulation of the system into a ROS2 publisher node that emits an /env/aggressiveness_index topic for downstream planners.

Prof. Daher's mid-January feedback added a fifth, more fundamental concern: the Q-learner's accuracy curve is tautological. Since the labels (Conservative / Normal / Aggressive) come from the same threshold rule that produces the AI score, and the agent only ever observes its own self-selected trajectories, the apparent learning is an artifact of the evaluation distribution. Addressing this concern conceptually drives most of the term's work and is the principal reason the new agent learns weights conditioned on context, rather than mapping scores to categories.

## **2. Work Completed This Month**

### **2.1 Roadmap and Repository Reorganization**

An honest audit of the repository in week 1 clarified that the supposed PyTorch DynamicWeightAgent referenced in the midterm did not yet exist as committed code. The only learning agent in the codebase was the numpy DriverQLearner. The term's PyTorch agent is therefore net-new code rather than a refactor. The repository was reorganized into model/ (AI math), agent/ (RL agents), env/ (simulator wrappers), notebooks/ (ad-hoc Jupyter exploration), and scripts/ (entrypoints). The Phase-1 scripts were moved to a legacy/ folder. Pinned dependencies via pyproject.toml: Python 3.11, PyTorch 2.2, gymnasium 1.0.0, highway-env 1.10.1, pandas 2.2, numpy 1.26.

A small breakage from the highway-env 1.10.1 upgrade was repaired: the configuration API changed from env.unwrapped.config.update(dict) to env.unwrapped.configure(dict). The legacy data_collector.py was patched in place and verified to still produce driving_behaviors_dataset.csv end-to-end.

### **2.2 Design Memo for the Self-Correctional Weight Predictor**

The new agent design fixes the input/output specification ahead of any code being written. Each step the agent receives a kinematic tuple (n_speed, n_accel, n_prox, n_wave) plus an environmental context vector (one-hot road type, normalized traffic density, normalized friction coefficient, weather flag). It outputs four AI weights (w_speed, w_accel, w_prox, w_wave) constrained to the simplex via softmax. The training loss is a combination of a supervised KL term against hand-picked per-regime target weights and an RL term that maximizes 1.0 − AI on non-crash episodes. The supervised targets are explicitly framed as anchors rather than ground truth — a design choice agreed with Prof. Daher in the week-1 sync that allows for an RL fine-tune phase later in the term.

### **2.3 PyTorch DynamicWeightAgent: First Forward Pass**

By the end of the month, the minimum viable agent (a 2-layer MLP, 8-dim input → 64 hidden → 64 hidden → 4-dim output, softmax) was implemented and tested for shape and gradient flow. A short training run on the cached Phase-1 CSV — augmented with synthetic per-row context tags via a heuristic loader — produced monotonically decreasing loss from 0.32 to 0.04 over 200 epochs. A held-out highway sample yielded predicted weights of (0.30, 0.10, 0.45, 0.15), which is within 0.01 L1 of the highway target. A perturbation evaluation (1000 small context-vector perturbations on a single urban telemetry row) showed a predicted-weight distribution that is tight in the (w_prox, w_wave) directions and broader in (w_speed, w_accel) — physically sensible for an urban regime.

Decision deferred per agreement with Prof. Daher: keeping the normalization saturation points constant (the 150 km/h saturation in N_speed, etc.) for term-2 to bound scope. Making them learnable parameters is logged as future work.

## **3. Results**

The MVP DynamicWeightAgent is functional. Forward and backward passes execute without error; loss decreases monotonically over 200 epochs; held-out samples produce predicted weights consistent with the regime-appropriate hand-picked targets. The architecture has been cleared as the foundation for the gating-network extension planned for February.

## **4. Plan for Next Month**

February will focus on three things. First, wiring the agent into the highway-env simulation loop so it produces predicted weights at each step and computes the AI score using those weights, then comparing the resulting AI scores to the fixed-weight baseline on controlled scenarios. Second, building the gating layer described in the midterm's future-work section: three learnable regime embeddings, a small MLP gate over the context vector, the predicted weight vector as the convex combination. Third, beginning the diagnostic infrastructure (Bellman-error tracking, state-visitation heatmaps) that will be needed to address Prof. Daher's memorizing-not-learning critique on the Q-learner side.
