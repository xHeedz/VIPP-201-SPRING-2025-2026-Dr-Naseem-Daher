# **Monthly Progress Report — May 2026 (Final Integration Coda)**

*Hadi Al Shmaissani · Project 3 · Supervisor: Prof. Naseem Daher*

**Abstract — **This short coda report covers the eight days from Saturday May 2 through Saturday May 9, 2026 — the post-deadline integration push that produced the agent-vs-ground-truth validation against a Gaussian sensor noise model. A routine final smoke test on May 2 surfaced a 100% agent-vs-ground-truth accuracy figure that turned out to be an info leak: both code paths were calling the same TraCI methods on the same vehicles. The fix required separating the system into two assessor classes — SumoGroundTruth reading exact telemetry, and SumoAgentAssessor reading the same telemetry with sensor noise added — which in turn surfaced three additional issues (scenario-specific reward functions that should have been unified; inconsistent IDM/MOBIL configuration on surrounding vehicles; a structural inability of the formula to produce Aggressive labels at the speeds the SUMO scenarios actually run at). All four were fixed across May 4–7, with calibration locked in May 8 and final results captured May 9. Final agent-vs-ground-truth accuracies across three scenarios with realistic Gaussian sensor noise: highway 91.0%, urban 81.6%, weather 88.3%, on a combined ~5400 vehicle samples — a meaningful validation that the closed-form Aggressiveness Index holds up under independent evaluation with sensor noise.

## **1. Introduction**

April closed with the term's technical work complete: the friction-aware regime in place, the ROS2 wrapper functional, and the Final Report drafted to ~38 pages with the submission scheduled for Sunday May 10. The week of May 2–9 was supposed to be buffer. A final smoke test on the morning of May 2 surfaced a problem the formal weekly testing had missed: the agent-vs-ground-truth accuracy in all three SUMO scenarios was 100%. That figure is a textbook bug signal — perfect agreement between two supposedly independent systems means they are not, in fact, independent. This coda report documents the discovery, the fix, and the resulting validation that the closed-form AI score holds up under realistic sensor noise on independent code paths.

## **2. The Info Leak and the Architectural Fix**

Investigation on May 2–3 traced the 100% accuracy to a structural problem. The "ground truth" code path and the "agent" code path were both calling the same TraCI methods on the same vehicles in the same simulation step. They produced perfect agreement because they were computing the same thing. There was no test of the agent's ability to estimate aggressiveness from limited or noisy observations.

The fix introduced two separate assessor classes. SumoGroundTruth reads exact TraCI values (speed, leader gap, lateral position) and represents the hand-calculated reference. SumoAgentAssessor reads the same TraCI values but adds Gaussian sensor noise BEFORE running the formula, representing what a real onboard sensor suite would observe. Noise applied at the input rather than the output is important — applying noise to the score after the fact would be a perturbation on the result, not a model of what a sensor system actually experiences.

The Gaussian noise model is calibrated to standard onboard sensor characteristics:

σ_vel = 0.5 m/s   (radar Doppler speed measurement)

σ_gap = 0.8 m     (lidar/radar range)

σ_acc = 0.3 m/s²  (polyfit on noisy speed history)

Acceleration is derived from a polyfit on the last several noisy speed samples rather than sampled directly, which produces a realistic noise-on-noise compound that matches how real onboard estimators behave. Independent samples per step, no temporal correlation; correlated time-domain noise is captured as a future-work item.

## **3. Three Adjacent Issues Surfaced and Fixed**

Once the architectural separation was in place, three additional problems became visible.

### **3.1 Unified Reward Function**

The reward function still had scenario-specific branches (highway_reward, urban_reward, weather_reward as separate functions). This meant the RL agent was technically training on three different reward signatures depending on scenario context — an overfitting risk that should have been addressed earlier. The fix merged all three branches into a single function (reward_function.py, ~60 lines) that takes (state, action, context including the regime flag) and returns a scalar. Cross-checked against the previous three-branch implementation on cached telemetry: reproduces previous rewards within floating-point precision when context matches the previous regime tag.

### **3.2 IDM/MOBIL on Surrounding Vehicles**

Surrounding vehicles in some configurations were using simple rule-based behavior rather than the realistic IDM (longitudinal car-following) and MOBIL (lane-change decisions) models we should have been using consistently. Walked through all SUMO routes files and set the IDM and MOBIL parameters explicitly on every vType (sigma=0.5 for driver imperfection, lcStrategic=1.0, lcCooperative=1.0, lcSpeedGain=1.0, lcKeepRight=0.0). Equivalent toggle in highway-env.

### **3.3 Four Root Causes for Zero-Aggressive-Label Output**

The first run with the new architecture produced ~95% agent-vs-ground-truth accuracy across all three scenarios — but on closer reading of the per-vehicle classifications, every vehicle was Conservative or Normal. Zero Aggressive labels in any scenario despite Aggressive vTypes being defined in the routes files. Four distinct root causes:

(1) The speed term in the formula was (speed_kmh / 150)². Squaring a fraction less than 1 makes it smaller. Combined with the 0.30 highway weight, the speed term contributed at most 30% — well below the 55% Aggressive threshold. Fix: switched to speed_ms / speed_ref (no square), with per-scenario reference speeds (highway 38 m/s, urban 22 m/s, weather 25 m/s).

(2) Proximity was measured to the ego vehicle rather than to each vehicle's actual leader. IDM vehicles do not tailgate the ego; they keep equilibrium gaps to whoever is directly in front of them. An aggressive vehicle two cars ahead of the ego was reading its (large) distance to the ego rather than its (small) distance to its actual leader. Fix: switched to traci.vehicle.getLeader().

(3) Weather had a double-counted speed reduction. The route file applied spd_scale=0.7 to all vehicle maxSpeeds (rain physics) AND the runner called traci.vehicle.setMaxSpeed() multiplied by friction (0.3). Aggressive weather vehicles ended up capped at ~9 m/s — crawling. Fix: removed all setMaxSpeed calls from the runner.

(4) Urban intersection arms had 2 lanes each, so aggressive vehicles lane-changed past conservatives, leaving them with no leader and a 150 m proximity reading. Fix: switched all four arms to 1 lane and added 8 explicit conservative→aggressive platoon pairs across the four arms.

## **4. Calibration**

Per-scenario formula calibration locked in on May 8: highway speed_ref=38 m/s, gap_ref=25 m, thresh_aggr=55%, noise_scale=1.5; urban speed_ref=22 m/s, gap_ref=17 m, thresh_aggr=50%, noise_scale=1.0; weather speed_ref=25 m/s, gap_ref=35 m, thresh_aggr=55%, noise_scale=1.0.

Two tuning rabbit-holes are recorded for completeness. First: weather noise scale was initially set to 1.5× by analogy to highway, but conservative weather vehicles sit at ~28% on the formula (only 2 percentage points below the C/N category boundary at 30%); 1.5× noise caused frequent flips to Normal and crashed accuracy to ~69%. Reverted to 1.0×. Second: highway accuracy at 97.7% felt suspiciously high; raising global SIGMAs to (0.8, 1.5, 0.4) brought highway to 88.8% but crashed urban to 75.9% and weather to 64.9% — those scenarios have populations sitting much closer to category boundaries and are hit disproportionately by global noise. Reverted to (0.5, 0.8, 0.3) and applied noise_scale=1.5 only to the highway call. Highway: 91.0%.

## **5. Final Results**

Final agent-vs-ground-truth accuracies across the three scenarios, with realistic Gaussian sensor noise applied to the agent's input but not to the ground-truth reference:

Highway (clear): 91.0% accuracy across 1328 samples; ground-truth distribution 589 Conservative / 717 Normal / 22 Aggressive.

Urban (intersection): 81.6% accuracy across 2284 samples; ground-truth distribution 1223 / 501 / 560.

Weather (rain/wet): 88.3% accuracy across 1825 samples; ground-truth distribution 833 / 837 / 155.

All three scenarios produce all three driver categories. There is no info leak — ground truth and agent assessor are completely independent code paths. Accuracy is in the realistic 80–91% range. The original target was 90–95%; urban falls below at 81.6%, attributable to the tight category boundaries × intersection-speed populations × sensor noise interaction. The mechanism is well-understood (intersection speeds put Normal and Aggressive populations close to the category boundary, where sensor noise more easily flips classifications) rather than reflecting a fundamental architectural problem.

## **6. Discussion**

The May 2–9 push closes a real gap in the original term's submission. The midterm and the term's main technical work demonstrated the closed-form AI score on telemetry that was, in retrospect, the same telemetry both the formula and the evaluation reference were computed from. That is not a sensor-noise validation. The May 2–9 work introduces a true sensor-noise validation: realistic Gaussian noise on velocity, range, and (compound) acceleration, applied to a fully separate code path, and the agent's classifications agree with the ground-truth reference at 81–91% across three scenarios. The whole point of the AI score is to be usable by a real onboard system with imperfect sensors, and this validation is what makes that claim defensible.

The lesson — caught for the second time this term, after week 5's diagnostic loop on the Q-learner — is that 100% on anything is a bug signal. Both times the symptom was a clean accuracy curve that was computed against a reference too closely tied to the agent's own inputs. The fix in both cases was to instrument carefully and look at what the agent is actually doing. The infrastructure mattered more than any individual model architecture choice.
